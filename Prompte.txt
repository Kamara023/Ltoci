Tu es un architecte logiciel senior, data scientist, ingénieur Machine Learning, expert en systèmes statistiques, expert backend/API, expert React Native et expert DevOps.

Je veux concevoir et développer une plateforme complète d'analyse statistique des jeux de loterie en Côte d'Ivoire, avec comme premier périmètre le Loto Bonheur de la LONACI.

IMPORTANT :
Le système ne doit jamais prétendre connaître ou garantir les futurs résultats d'un tirage.
Les tirages de loterie sont considérés comme aléatoires et indépendants.
Le projet doit donc être présenté comme une plateforme d'ANALYSE STATISTIQUE, de MODÉLISATION et de GÉNÉRATION DE COMBINAISONS CANDIDATES basées sur les données historiques.

Le projet doit être conçu comme un véritable produit logiciel évolutif, maintenable et potentiellement transformable en SaaS.

==================================================
1. OBJECTIF DU PROJET
==================================================

Créer une plateforme capable de :

1. récupérer automatiquement les résultats historiques disponibles ;
2. récupérer régulièrement les nouveaux résultats ;
3. nettoyer et normaliser les données ;
4. stocker l'ensemble des tirages dans une base de données ;
5. analyser statistiquement les tirages ;
6. détecter des tendances et régularités statistiques ;
7. calculer différents indicateurs sur les numéros ;
8. construire des modèles statistiques et de Machine Learning expérimentaux ;
9. générer plusieurs combinaisons candidates ;
10. expliquer pourquoi chaque combinaison a été générée ;
11. comparer les performances historiques des différentes stratégies ;
12. mesurer objectivement la qualité des modèles par backtesting ;
13. afficher toutes les informations dans une application mobile et une interface web ;
14. permettre l'évolution future vers plusieurs jeux et plusieurs sources de données.

Le produit doit être pensé comme une plateforme DATA + ANALYTICS + AI et non comme un simple générateur de numéros.

5. ANALYSES STATISTIQUES
==================================================

Implémenter au minimum :

A. Fréquence globale

Calculer :

- fréquence de chaque numéro ;
- fréquence relative ;
- fréquence par période ;
- fréquence annuelle ;
- fréquence mensuelle ;
- évolution de fréquence.

B. Numéros chauds / froids

Identifier :

- numéros fréquemment observés ;
- numéros moins fréquemment observés ;
- évolution récente ;
- comparaison court terme / moyen terme / long terme.

Ne jamais interpréter automatiquement un numéro froid comme "plus susceptible" de sortir.

C. Retard

Calculer :

- nombre de tirages depuis la dernière apparition ;
- retard moyen ;
- retard maximum historique ;
- distribution des retards.

D. Paires / triplets / groupes

Analyser :

- paires fréquentes ;
- triplets fréquents ;
- cooccurrences ;
- associations statistiques ;
- fréquence des associations.

E. Consécutifs

Analyser :

- présence de nombres consécutifs ;
- nombre de consécutifs par tirage ;
- fréquence historique des configurations.

F. Pair / impair

Analyser les distributions :

- 0/100 ;
- 1/99 ;
- etc. selon le format réel du jeu.

Ne pas inventer les formats.
Le système doit automatiquement adapter l'analyse aux règles du jeu.

G. Haut / bas

Analyser la distribution des numéros faibles et élevés selon l'intervalle réel du jeu.

H. Somme des numéros

Calculer :

- somme totale ;
- moyenne ;
- médiane ;
- min ;
- max ;
- distribution historique.

I. Dispersion

Analyser :

- écart entre minimum et maximum ;
- dispersion ;
- concentration ;
- répartition sur l'intervalle.

J. Répétition entre deux tirages

Mesurer :

- nombre de numéros répétés ;
- fréquence des répétitions ;
- distribution historique.

K. Fenêtres temporelles

Toutes les analyses doivent pouvoir être effectuées sur :

- historique complet ;
- 100 derniers tirages ;
- 50 derniers tirages ;
- 20 derniers tirages ;
- 10 derniers tirages ;
- période personnalisée.

==================================================
8. GÉNÉRATION DE COMBINAISONS
==================================================

Créer un moteur de génération de combinaisons candidates.

Le moteur doit :

1. générer un grand ensemble de combinaisons candidates ;
2. calculer un score pour chaque combinaison ;
3. appliquer des contraintes statistiques ;
4. éliminer les combinaisons excessivement similaires ;
5. sélectionner les meilleures candidates ;
6. fournir une explication du score.

Exemple de score :

CombinationScore =
    fréquence
    + récence
    + cooccurrence
    + équilibre pair/impair
    + équilibre haut/bas
    + dispersion
    + diversité
    - pénalités statistiques

Les coefficients doivent être configurables.

Ne jamais présenter ce score comme une probabilité réelle de gagner.

==================================================
10. BACKTESTING
==================================================

C'est une fonctionnalité obligatoire.

Le système doit simuler ce qui aurait été produit par le modèle dans le passé.

Exemple :

Utiliser les tirages 1 → 500
pour générer une combinaison pour le tirage 501.

Puis :

tirages 1 → 501
→ prédiction 502.

Continuer jusqu'au dernier tirage disponible.

Mesurer :

- nombre de correspondances ;
- moyenne de correspondances ;
- distribution des résultats ;
- performance par stratégie ;
- performance par période ;
- performance de chaque modèle ;
- comparaison avec sélection aléatoire.

Afficher clairement les résultats.

==================================================
11. VALIDATION DES MODÈLES
==================================================

Interdire le data leakage.

Un modèle ne doit jamais utiliser les résultats futurs pour prédire un tirage passé.

Utiliser :

- Time Series Split ;
- Walk Forward Validation ;
- Backtesting temporel ;
- séparation stricte train/test.

Comparer systématiquement :

MODEL
vs
RANDOM BASELINE

Calculer des métriques adaptées au problème.

12. IA
==================================================

L'IA ne doit pas inventer les données.

Elle doit recevoir les résultats statistiques calculés par le backend.

Créer un module AI Analyst capable de transformer les statistiques en explications compréhensibles.

Exemple :

"Le numéro X présente une fréquence supérieure à sa moyenne historique sur les 50 derniers tirages, mais son retard actuel reste proche de sa moyenne historique."

L'IA doit distinguer :

- faits observés ;
- statistiques ;
- hypothèses ;
- interprétation ;
- limites.

Elle ne doit jamais dire :

"Le numéro X va sortir."

Elle peut dire :

"Selon le modèle, cette combinaison obtient un score statistique supérieur aux autres candidates."
